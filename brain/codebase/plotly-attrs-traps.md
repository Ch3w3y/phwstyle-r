# plotly attrs traps

What `phw_plotly()` has to know about an unbuilt `plot_ly()` object.

- Each entry of `p$x$attrs` is evaluated against the data stored under its own name: `plotly::plotly_data(p, names(p$x$attrs)[i])`. There is no `visdat` field on an attr. Reading `visdat[[1]]` gives every `add_trace(data = ...)` trace the first trace's data.
- Colour mapping, discrete or numeric, uses only the first trace's `colors`, for every trace, even when the first trace maps no colour. Give all traces one shared vector, plain ones included.
- A trace with no colour mapping takes `colorway[i]`, where `i` is its place among all built traces. A plain line before the groups takes colorway slot 1, which is the first group key colour, so `phw_plotly()` drops the key's colours from the colorway.
- A named `colors` vector is matched by name (`scales::col_factor(levels = names(pal))`). An unnamed one is spread over all levels, unused ones included, and interpolated when it is shorter.
- Missing values are always `transparent`: `map_color()` hard-codes `na.color`. Map them to an "NA" group instead. plotly already names that trace "NA".
- `phw_colour_key()` overflow warnings fire at most once every 8 hours, so a test that expects one needs `withr::local_options(rlib_warning_verbosity = "verbose")`. With verbose on, it warns once per overflow group: use `capture_warnings()`, not `expect_warning()`.
- A `subplot()` figure is already built: `p$x$data` holds the traces and `p$x$attrs` are marked `plotly_eval` with no data left to evaluate them. plotly marks the colours it picked with the classes `colorway` (no colour mapping) and `plotly_default` (groups, scales). `colors =` and `I()` colours are `plotly_default` too, so the attrs are the only way to tell them apart. `plotly_default` also marks non-colours such as `colorbar$title` and numeric `marker$color`.
- In a `subplot()` figure the missing group's trace is named `NA` (`NA_character_`), not `"NA"`: plotly turns it into `"NA"` only in `plotly_build()`. Code in `phw_plotly()` sees the unbuilt name, tests see the built one. A panel's own `colors` leave that trace `"transparent"` too, so match it by name to grey it.
- When you replace a classed value, keep its class. A plain value makes plotly think the user set `marker` or `textfont`, and it warns and adds them to the trace's `mode`.
- `plotly_build()` merges `p$x$layout` and each `layout()` call with `modify_list()`: a list value replaces a string one, so `title = list(font = ...)` deletes a string title's text. An axis title from `x = ~col` is set with `%||%` after the merge, so any `xaxis$title` you set blocks it. Colour axis titles with the axis `color` instead: plotly.js uses it as the default title and tick label colour. Those automatic titles carry the class `plotly_default`, so compare them with `unclass()` in tests.
- Leave `showlegend` unset unless you mean it. plotly sets it to `sum(trace showlegend) > 1` (or a single pie) only when nothing set it before.
- `phw_plotly(legend = )` takes the name of plotly's layout `legend`, so `...` can never pass a layout legend. Only `margin` and the rest reach `layout()`.
- plotly cannot stack a bottom legend and the source annotation: the legend `y` is a fraction of the plot height and its row count depends on the width. `inst/js/plotly-bottom-legend.js` measures what was drawn on each `plotly_afterplot` and relayouts. Compute the legend `y` from the plot height plotly drew (`_fullLayout._size.h`), not from `height - t - margin.b`: a range slider adds its own height on top of `margin.b`.
- Never find an annotation by its index in the hook. `ggplotly()` puts a faceted chart's axis titles and strip labels first (`annotationType = "axis"` for the titles), and annotations from an earlier `layout()` come before the source line too. The source annotation carries `name = "phw_source"`, and the hook looks it up by that name.
- Screenshots in headless Firefox are taken at the load event, so a `setTimeout` never shows. To see async output, such as a `Plotly.toImage()` result, use `google-chrome-stable --headless --virtual-time-budget=5000 --screenshot=...`. plotly 4.10.4 (plotly.js 2.11.1, the oldest supported) installs from the CRAN archive tarball. The Posit binary URL silently serves the latest version.
- `ggplotly()` builds a ggplot with its own copy of the build steps and skips the palette a ggplot2 4.0 theme sets, so `use_phw_ggplot()` does not reach it: groups come out in ggplot2's hue colours as plain, unclassed `rgba()` strings. Its `attrs` hold the ggplot mapping (`colour = ~~g`), not plotly's `color`, so `sets_colours()` and `maps_colours()` never see it. Nothing in a built ggplotly trace says whether a scale was the default. Only the colour value shows it, which is why `colour_built()` matches `scales::hue_pal()`. The trace name is not the colour group: a trace split by colour and shape is named `(A,1)`, and the same level can get different hue colours in two ggplots of one `subplot()`. Group by panel and hue colour, then name the group by the value its trace names share.
- `ggplotly()` also skips a theme's continuous palette, so numbers come out in ggplot2's default gradient (`#132B43` to `#56B1F7`): hex colours in a `colorscale` data.frame and per-mark `rgba()` vectors, unclassed. `rapply()` descends into the data.frame columns. `regradient()` looks each colour up on the gradient (within one RGB step) and swaps in the PHW colour at the same place, but only when the figure holds both exact ends of the gradient (the default scale gives them to its lowest and highest values). Per-colour matching alone recoloured PHW's own `gradient` palette where it crosses the default gradient near `#326791`. Expect the result to differ from `phw_plotly(g)` by up to one RGB step.
- Why `ggplotly()` names traces "(A,1)": it splits each layer by every discrete legend scale of the whole plot, then by `PANEL`. A layer without one of those scales (bars with `fill` next to a line with `colour`) takes the panel number in that slot. `plain_legend()` in `ggplotly_phw()` renames such traces to the group and shows each group once, preferring a plainly named trace. A real two-legend chart (colour by one column, shape by another) keeps its tuples.
- A `subplot()` drops `visdat`, so `tidy_ggplotly()` cannot read the legend keys from the data. `panel_keys()` infers them per panel: when every "(A,1)" of a panel ends in the same number, that number is the panel, not a second legend. A shape level that is itself a number such as "1" looks like a panel number, so tests of a two-legend chart should use letters for the second legend.
- ggplot2 gives a fill scale and a colour scale the same first hue (`#F8766D`), so an average line mapped to `colour = "Average"` shares its colour with the first fill group. `ggplot_groups()` keys a plainly named trace by its name as well as panel and hue.
- A top-anchored title (`yref = "container"`, `yanchor = "top"`) on more than one line starts 0.7em (12px at 17px) higher than a one-line title: each line's tspan carries its own `y`, so the text's `dy` is lost. Same in plotly.js 2.11.1 and 2.25.2. A bottom-anchored title still grows downward. `ggplotly()` keeps `\n` in a title, not `<br>`, and plotly.js breaks lines on both.
- `ggplotly()` draws top facet strips as shapes with `ysizemode = "pixel"`, `y1` = strip height, anchored at the panel top. Right strips use `xsizemode`; panel backgrounds have neither.
- To check where plotly drew something, add an `htmlwidgets::onRender()` probe that writes `getBoundingClientRect()` values into a `<pre>`, then read it with `google-chrome-stable --headless --virtual-time-budget=5000 --dump-dom`.
- plotly.js draws only an axis that a trace is on. An overlaying axis (`yaxis2` with `overlaying = "y"`) and no trace on it does not show at all, so `secondary_axes()` puts an empty trace on it.
- `plotly::subplot()` renames each chart's axes and updates `anchor`, but not `overlaying` or `matches`. A second chart's overlay keeps pointing at `y`, and its panel draws blank. `overlay_own_panel()` re-points it to the main axis with the same anchor, but only when the combined figure goes through `phw_plotly()`.
- Test for a ggplot secondary axis with `inherits(scale$secondary.axis, "AxisSecondary")`. A discrete scale with none has `NULL` there, not a waiver. `panel_params$y.sec` exists for every continuous panel, mirroring the main axis when there is no secondary axis.
- A `ggplotly()` figure keeps no ggplot, but each `attrs` entry (class `plotly_eval`) holds one layer's ggplot mapping as `~<quosure>` (or `~<constant>` for `aes(linetype = "Target")`), and `visdat[[id]]()` returns that layer's data. `rlang::eval_tidy(rlang::f_rhs(f), data)` gives the mapped values; `after_stat()` mappings fail and must be caught. `tidy_ggplotly()` gets legend values and `text` values this way.
- With the default `tooltip = "all"`, ggplotly's hover is one `<br />`-separated line per aesthetic, each `"<label>: <value>"` except `text`, which has no prefix. A `geom_text()` trace keeps its label in `text` and the hover in `hovertext`, so never overwrite `text` on a `mode = "text"` trace.
- `ggplotly()` gives every theme text (legend, legend title, tick labels, axis titles and strip annotations) the theme's bare family, such as `"Ubuntu"`, with no fallback. plotly.js measures text before the Ubuntu web font loads, and Chromium then measures it in its serif default, so legend items overlap and labels are cut off (#417). Firefox hides this. `font_fallback()` in `phw_plotly()` swaps the bare PHW family for the base stack. To see it, measure in `google-chrome-stable --headless --dump-dom` with an `onRender()` probe, not in Firefox.
