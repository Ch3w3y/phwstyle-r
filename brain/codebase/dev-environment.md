# Development environment on this machine

```sh
RB=~/.uvr/r-versions/4.5.3/bin                       # R is not on PATH
D=~/.cache/phwstyle-dev                               # shared; read-only except $D/wt/ and the TinyTeX reinstall (below)
export R_LIBS="<your own lib>:$D/rlib"                # every dependency, testthat, roxygen2, pkgload, rcmdcheck
export PATH="$D/tools/pandoc-3.6.4/bin:$PATH"         # Pandoc
```

- Install the package under test into a NEW library of your own (`$RB/R CMD INSTALL --no-docs --library=<your lib> <dir>`), first on `R_LIBS`. Never write into `$D`, except worktrees under `$D/wt/` and the TinyTeX reinstall below. If a package is missing, install it into your own library from `https://packagemanager.posit.co/cran/__linux__/manylinux_2_28/latest`.
- ggplot2 3.5.1 is in `$D/gg35`. Put it first (`R_LIBS="$D/gg35:<your lib>:$D/rlib"`) to test old-ggplot2 behaviour. patchwork does not load there, so `phw_arrange()` tests skip.
- **The oldest CI setup** (the `oldest (CRAN 2024-10)` job in `.github/ci-matrix.json`) is installed too: R 4.3.3 in `~/.uvr/r-versions/4.3.3`, packages from the CRAN snapshot of 2024-10-14 with ggplot2 3.5.0 in `$D/oldest-lib`, Quarto 1.5.57 in `$D/tools/quarto-1.5.57` and Pandoc 2.19.2 in `$D/tools/pandoc-2.19.2`. Render tests that pass on current versions can fail there (#407, #421, #445 and #447 each failed that job after review). To run a test file on it:
  `RB3=~/.uvr/r-versions/4.3.3/bin; export R_LIBS="<your lib>:$D/oldest-lib" NOT_CRAN=true PATH="$D/tools/quarto-1.5.57/bin:$D/tools/pandoc-2.19.2/bin:$PATH" QUARTO_PATH=$D/tools/quarto-1.5.57/bin/quarto TAR=$(which tar)`, install the package with `$RB3/R CMD INSTALL --no-docs --library=<your lib> <dir>`, then `cd <dir> && $RB3/Rscript -e 'testthat::test_local(".", filter = "<file>", load_package = "installed")'`, where `<file>` is the test file's name between `test-` and `.R`, such as `formats`. `sf` and its map tests are missing there, because the system has no Fortran compiler or udunits; map tests skip.
- There is no devtools. Use `pkgload::load_all()`, `testthat::test_local()` and `roxygen2::roxygenise()`.
- To wait for a run you started in the background, keep its PID (`cmd & pid=$!`) and `wait "$pid"`. `wait` only works in the shell that started the run. To wait from a later command, save the PID when you start the run (`cmd & echo $! > <scratch>/run.pid`), then poll it: `pid=$(cat <scratch>/run.pid); while kill -0 "$pid" 2>/dev/null; do sleep 10; done`. Never poll `pgrep -f "<part of its command>"`: the polling shell's own command line contains that text too, so the loop never ends and the stage hangs after its work is done (this happened in #236 and #305).
- Every R process prints Fontconfig noise on stderr: filter with `2>&1 | grep -v Fontconfig`.
- `R CMD check --as-cran` on a clean `git archive` tarball gives 5 WARNINGs and 6 NOTEs from fontconfig noise on main. Anything beyond that list is new. A seventh NOTE, "unable to verify current time", appears when the time server is unreachable and is not from the code. CI on GitHub is the real gate and fails on any WARNING.
- Rendering outputs: [[codebase/render-pptx-with-libreoffice]] (PowerPoint, Word, Excel); HTML via `firefox --headless -profile "$(mktemp -d)" --screenshot /abs/out.png --window-size=1280,1200 file:///abs/page.html`.
- The user's boundaries cache is in `tools::R_user_dir("phwstyle", "cache")`. Never delete it: set `R_USER_CACHE_DIR` to a scratch folder for any probe that clears caches.
- Tests that build bslib pages warn "problem copying ... bootstrap.bundle.min.js: Permission denied": bslib copies files from the read-only shared library and keeps their read-only mode. These are warnings, not failures, and happen on main too.
- Quarto 1.11.9 is installed in `~/.cache/phwstyle-dev/tools/quarto-1.11.9`, linked from `~/.local/bin/quarto`. TinyTeX is installed in `~/.cache/phwstyle-dev/tools/tinytex`, and its commands (`xelatex`, `lualatex`, `pdflatex`, `tlmgr` and the rest) are linked from `~/.local/bin`. So the PDF and Quarto render tests run. `testthat::test_local()` sets `NOT_CRAN=true` itself; under `R CMD check` or a bare `test_file()`/`test_dir()`, set `NOT_CRAN=true` or they skip as "On CRAN". Render the Quarto formats (`phw-html`, `phw-docx`, `phw-pptx`, `phw-pdf`, plus `phw-typst`, `phw-revealjs` and `phw-dashboard`) when a change touches them; do not call that path untested. Never install LaTeX into a scratch folder: `/tmp` is cleared on reboot, which leaves the `~/.local/bin` links pointing at nothing.
- If `xelatex` stops working, reinstall TinyTeX in the same place: `TAR=$(which tar) $RB/Rscript -e 'tinytex::install_tinytex(dir = "~/.cache/phwstyle-dev/tools/tinytex", add_path = FALSE, force = TRUE)'`. Without `TAR`, tinytex calls a missing `gtar` and installs nothing. `force = TRUE` is needed because `~/.local/bin/tlmgr` and the existing folder would otherwise stop the install; it deletes the old folder first, and the loop below replaces the links. Do this only when `xelatex` fails, and say so in the PR. Then link its commands with `for f in ~/.cache/phwstyle-dev/tools/tinytex/bin/x86_64-linux/*; do ln -sf "$f" ~/.local/bin/; done`.
