# Table renderer traps

- **gt spanner ids share one namespace with column names.** `gt::tab_spanner()` stops when its `id` equals a column name, and `phw_gt()` passes a summary table's real names to gt so later gt steps find them. Make spanner ids unique against the column names (`style_summary_gt()`).
- **gt drops attached HTML dependencies.** `gt:::as.tags.gt_tbl()` rebuilds the HTML and loses anything attached with `htmltools::attachDependencies()`. `phw_gt_theme()` adds the class `phw_gt`, whose `as.tags` method attaches `phw_font_dependency()`. An HTML dependency in any pandoc format other than HTML stops the render ("Functions that produce HTML output found"), and gt's `knit_print()` goes through `as.tags()` for Typst and pptx, so `knit_print.phw_gt()` drops the class there. Keep the dependency when `knitr::pandoc_to()` is NULL: `is_html_output()` is FALSE then. Quarto turns gt's HTML into a real table for Typst and pptx; R Markdown pptx drops it, so a note on the console points to `phw_flextable()`. Tell Quarto from R Markdown with `knitr::opts_knit$get("quarto.version")`.
- **flextable HTML names a font but ships none.** Its CSS says `font-family:'Ubuntu'` with no fallback, so without the font file a browser draws serif. `phw_flextable` adds `phw_font_dependency()` in `knit_print()` (HTML output), `as.tags()` and `print()` (Viewer). `flextable::htmltools_value()` is not generic, so plain calls to it stay without the font.
- **htmlwidgets ignore `attachDependencies()`.** An htmlwidget renders from its own `$dependencies` list, so add the font with `w$dependencies <- c(w$dependencies, list(phw_font_dependency()))` (DT, leaflet, reactable, plotly). Test it by saving the page with `htmltools::save_html()` and looking for `phw-ubuntu`.
- **Quarto needs every HTML dependency on disk.** Quarto copies each dependency with `htmltools::copyDependencyToDir()`, which stops on one without `src$file` ("Dependency phw-dt 0.1 is not disk-based"). R Markdown, the Viewer and Shiny accept `src = c(href = "")`, so only a Quarto render catches it (#455). Build inline-CSS dependencies with `phw_style_dependency()` in R/fonts.R.
- **openxlsx2 `wb_add_font()` defaults `size` to 11.** Pass the size every time, or bold rows come out larger than the 10pt body.
- **One row model for all renderers.** `summary_rows()` in R/summaries.R decides shading, bold, italic, navy, rules and indents for every summary and group row. Change the look there, not in one renderer, so the five stay the same.
- **One header model too.** `summary_header()` in R/office.R gives the spanner or the upper header levels as runs, with a `total` flag for grand total columns. DT, xlsx, gt and reactable hide a total's upper labels. flextable keeps them so `merge_v()` joins the total into one tall cell.
- **One number-format rule too.** `year_cols()` in R/labels.R marks year columns (whole numbers 1800 to 2200, name with "year", "yr" or "blwyddyn"), which every renderer shows without a thousands separator. A new per-column format belongs beside it, not in one renderer.
- **flextable `colformat_double()` skips integer columns.** `2021:2024` is integer, so use `colformat_num()` to reach both types. Mask a subset as `is_int & !is_year` at each call: overwriting `is_int` sends the subset into the `!is_int` decimal branch.
- **Red, amber, green:** `rag_status()` in R/flextable.R classifies values for `phw_flextable_heat()` and `phw_col_rag()`.
- **Shading rule:** shade variable and group rows when `attr(x, "highlight") %||% TRUE`.
- To compare all five renderers by eye, render the same inputs through each one and montage the screenshots: HTML via headless Firefox, docx and xlsx via the `phw-lo-writer` image ([[codebase/render-pptx-with-libreoffice]]).
- **DataTables `columnDefs`: earlier definitions win.** DataTables 1.13 reads the array from last to first, so the first definition that sets a property wins. `className` is the exception: classes add up, and `dt-right` beats `dt-left` in the stylesheet. `utils::modifyList()` replaces unnamed lists whole, so join `columnDefs` with `c()`, never through `modifyList()`.
- **New per-row or per-column attributes must be subset in `[.phw_summary`** (R/summaries.R). It subsets `row_type`, `depth`, `group_start` and `col_header`, and copies the rest unchanged. dplyr's `filter()`/`slice()`/`arrange()` reach it through `dplyr_row_slice.phw_summary`. In R, `!` binds looser than `>`, so `nargs() - !missing(drop) > 2` parses as `nargs() - !(missing(drop) > 2)`. Compute the count first.
- **flextable's LaTeX caption is always numbered.** flextable writes `set_caption()` text into `\caption{}` (and `\caption[]{}` on the repeated header), so LaTeX adds "Table N." in front. `phw_flextable()` already puts the number in the text, so its class `phw_flextable` has a `knit_print` method that swaps in `\caption*{}` for LaTeX output. A header-wide `labelformat=empty` would also strip the labels of kable, pandoc and Quarto `#tbl-` tables. gt already uses `\caption*`. A test can check this without LaTeX: `rmarkdown::render(rmd, phw_pdf_document(), output_file = "x.tex")` writes the `.tex` only.
- **gt's Word caption is always numbered too.** `gt::as_word()` puts a "Table n: " SEQ field before the title, and gt's own `knit_print` calls it with defaults. `knit_print.phw_gt()` writes the Word XML itself through `gt_word_xml()`: `autonum = FALSE` from gt 1.1.0, and a regex that removes the field on 0.10.1 to 1.0.0, which have no such argument. Check caption text in a render with `//w:p[w:pPr/w:pStyle/@w:val = 'caption']`.
- **A test that renders with a phw format must call `local_ggplot_state()`.** The formats style charts before knitting. Without the guard, ggplot tests later in the run fail with a different set each run (axis sizes, plotly titles, default scales), and each passes when run alone.
- **PowerPoint never draws a flextable caption**, through officer or knitr (flextable's `knit_to_pml()` ignores `set_caption()`). `caption_as_header()` in R/office.R turns it into the table's top row: `phw_add_slide()` calls it, and so does `knit_print.phw_flextable()` for pptx output.
- **Quarto drops a flextable caption from `set_caption()`.** flextable 0.10.x writes an empty caption in HTML, Word, LaTeX and Typst when `opts_knit$get("quarto.version")` is set, and leaves it to the chunk's `tbl-cap`. `knit_print.phw_flextable()` calls `caption_as_header()` there unless the chunk sets `tbl-cap`. Quarto captions a raw Word table from `tbl-cap` only with a `tbl-` label, so without one `word_tbl_cap()` (R/office.R) hands the `tbl-cap` to the table: a flextable makes it the caption row, a gt table puts a `Table Caption` paragraph above (the style pandoc gives a `kable()` caption). Quarto's Typst writer drops an unlabelled `tbl-cap` for every table, `kable()` too. In HTML, `tbl-cap` also lands in a `data-tbl-cap` attribute, so strip tags before counting caption text.
- **flextable's Word writer takes the line between two rows from the upper row's bottom border** and ignores the lower row's top border. A row added above the header (the caption row) must carry the table's top rule as its own bottom border, or Word shows no rule; HTML and LaTeX draw it either way.
- **Fitting a flextable to a document page happens in `knit_print.phw_flextable()`**, only for docx, Typst and LaTeX, so HTML and slides keep the autofit widths. The PHW text width is A4 less 2 cm side margins (6.69 in), in Word, PDF and the `phw-typst` template alike. flextable writes Typst columns as fixed `in` widths that include the cell inset, so Typst takes the Word budget unchanged; check a render with `keep-typ: true` and sum the `columns: (...)` widths. LaTeX adds `\tabcolsep` (flextable's 2 pt by default) either side of every `p{}` column, so the LaTeX budget is the text width less `ncol * 4` pt.
- **Measure wrapped widths by putting `\n` in the chunk text** of a copy and calling `flextable::dim_pretty()`: that gives each column's widest word. `dim_pretty()` ignores merged cells, so a long source line in the footer does not widen the table.
- **gt tables in PDF are longtables, never floats.** From gt 0.11.1 gt writes a `table` float, which LaTeX can't break, so a table longer than the page ran over the footer. `knit_print.phw_gt()` sets `latex.use_longtable` and repeats the header with `\endhead` (gt's `latex.header_repeat` from 1.1.0). A longtable can't go in `\resizebox`, so `fit_gt_latex()` measures the table in a box and, when it is wider than the text, scales the font and `\tabcolsep` by text width / table width. Full width comes from `@{\extracolsep{\fill}}` with `\LTleft` and `\LTright` at `0pt plus 1fil`. At a rigid `0pt` the caption package puts the caption in a zero-width box and LaTeX logs an Overfull \hbox. Pandoc reads this raw LaTeX line by line and prints a `%` at the end of a line as text, so the fit code has none.
- **LibreOffice joins Word tables that follow each other with nothing between them**, so three tables printed from one chunk look like one table with mixed headers. Put text or separate chunks between them before judging a render.
- **gt's Word writer reads cell styles only.** `gt::as_word()` (what gt's `knit_print()` uses for docx) ignores `tab_options()` and `opt_table_font()`, so set anything Word needs with `tab_style()`. It takes one font name: a `cell_text(font = c(...))` list becomes one invalid name, and a single cell font in HTML replaces the web-font stack, so `knit_print.phw_gt()` adds `phw_font()` for docx only. As of gt 1.4.0 it never writes `w:ind`, collapses leading spaces, and drops the weight on column label and stubhead cells, so gt in Word can't indent levels or bold column labels: use flextable there.
- **flextable writes images and links in a Word table as file paths and URLs**, for officer to turn into relationships. A knitted .docx keeps them as they are and Word calls it corrupt. `phw_word_document()` sets the chunk option `is_rdocx_document = TRUE` (which also stops flextable's warning and lets `set_caption(autonum = )` number) and its post-processor `link_docx_files()` runs `officer::read_docx()` and `print()` on the file, only when `word/document.xml` has an `r:embed` or `r:id` that is not an `rId`.
- **flextable drops images from PowerPoint tables without a word**: its slide writer leaves an empty run for each one. `check_no_images()` stops `phw_add_slide()` and a knitted deck instead.
- **Chaining a format hook: `force()` the old one.** `fmt$post_processor <- wrap(fmt$post_processor)` with a lazy argument reads the new hook when it first runs and recurses until the node stack overflows.
- **Quarto's `tbl-cap` filter rewrites raw LaTeX.** Without a `tbl-` label, Quarto wraps the first `\begin{tabular}` in a raw block in a `table` float, and counts every raw block with a table environment as a separate table (two tables put the caption in a paragraph under them). A float in `\sbox0` stops the PDF ("Not in outer par mode", #446), so `fit_gt_latex()` writes its measuring table as `\tabular ... \endtabular`, which the filter's patterns skip. Keep any table environment that is not the real table out of the raw LaTeX a chunk prints. A longtable with no `\caption{` is also renamed `longtable*`. Test with a `tbl-cap` chunk both with and without a label.
- **XeLaTeX has no font fallback, and Ubuntu lacks most symbols** (it has ◊ but no ▲ ■ ▼). `phw-header.tex` sends ▲ ■ ▼ to DejaVu Sans, or Latin Modern Math (the only font in a default TinyTeX that has them), through XeTeX interchar classes. A new symbol in table text needs adding there. Check a PDF render for symbols by grepping the `.log` for "Missing character" (`options(tinytex.clean = FALSE)` keeps it).
- **Row names: labels or row numbers.** `check_table_data()` shows text row names as a first column unless a column already holds them (`labels_in_column()`) or they are row numbers (`is_row_numbers()`). `rbind()` stores row numbers as text only when subsets share some, and `make.unique()` turns a repeat of "3" into "31", then "32", skipping names in use, so "12" copies "1" only when "11" exists (`is_copy()`). Bound row numbers can come out sorted, so sorted is not enough to tell them from years, weeks or ages from `table()`. Each string-only rule broke a neighbour (#339, #352, #365, #375 twice): before changing it, score it with a harness of labels (years both ways, weeks and months with gaps, ages) against real `rbind()` output (verdict cases, random subsets of 10 to 100-row frames, 2 and 3 yearly filters of 7 and 22 areas). Some names are both (`1 2 3 7 11`), so aim for a measured miss rate, not zero. With 7 health boards, bound subsets come out sorted as text (`5 51 7`), so text order is no sign of labels.
- **Slide tables go through `slide_table_pages()`** (R/slide-table.R), for both a knitted deck and `phw_add_slide()`: caption row, text raised to 12 pt, width fit with `floor = "all"`, then with `grow` (a knitted `phw_flextable()`, or `phw_add_slide(table_fit = TRUE)`) `grow_to_area()` raises the text up to 18 pt, picking the largest size that takes no more slides than at 12 pt, then row heights from wrapped line counts, then body rows split over slides. Growth runs on the whole table before the split, so every slide of a table shows one size. Never let a growth or widening factor go below 1: a table still too wide after wrapping would have its columns squeezed past its words. A knitted deck starts each continuation slide with `---` (pandoc starts an untitled slide at a horizontal rule). Row heights are minimums on slides, so a model that underestimates lets the table run off the bottom.
- **`flextable::delete_rows()` turns a one-column dataset into a vector** (`dataset[-i, ]` with no `drop = FALSE`), and `nrow_part()` then fails. Reset `body$dataset` after deleting rows.
- **systemfonts 1.2.4 replaced `string_width(bold = )` with `weight = `**, and the old argument warns as deprecated in tests. Check `formals()` (see `text_widths()`).
- **A knitted deck's slide size comes from its reference document** (`knit_slide_area()` in R/flextable.R), not the PHW 13.33 x 7.5 in. R Markdown passes it in `knitr::opts_knit$get("rmarkdown.pandoc.args")` after `--reference-doc`. Quarto passes only `--to pptx` there; its resolved format, extension and `_quarto.yml` included, is in the JSON file named by `QUARTO_EXECUTE_INFO`, at `format$pandoc$"reference-doc"`, relative to the document's folder (`knitr::current_input(dir = TRUE)`). Quarto 1.5 (CI's oldest job) sets no `QUARTO_EXECUTE_INFO`; the same list is the `format` argument of its R `execute()`, found by walking `sys.frames()`. Test that path with that Quarto: the old-version CI job is the only gate that runs it. With no reference document pandoc uses its own deck, 10 x 5.625 in (`pandoc --print-default-data-file reference.pptx`). `opts_knit$get("quarto.version")` tells Quarto from R Markdown.
- **Quarto's pptx writer draws a cross-reference float only when it holds a picture.** A `tbl-` chunk wraps its table in a `FloatRefTarget`, and Quarto's pptx renderer replaces anything but an image with nothing ("PowerPoint output for FloatRefTargets require a single image as content"). `phw-slide-tables.lua` runs `at: pre-render` (after crossref numbering, so `@tbl-x` still resolves) and returns the float's blocks with every Div flattened: pandoc's pptx writer drops a raw `openxml` block nested in a Div, and only starts a slide at a top-level horizontal rule. A user filter listed before `quarto` already sees `FloatRefTarget`s, but unwrapping there loses the cross-reference. Quarto's pptx shows no `tbl-cap` for a flextable, so `knit_slide_table()` makes it the caption row.
- **flextable 0.9.6 writes a bare "header1" into each Word header row**, as text directly inside `<w:tr>`, outside any run. `xml_text()` on a row then starts with "header1" on the oldest CI job only (#447). Read a row's visible text from its runs: `paste(xml_text(xml_find_all(row, ".//w:t")), collapse = "")`. To test an older flextable, install it from the 2024-10-14 Posit snapshot into your own library with `dependencies = FALSE` and run only the tests that matter: newer gdtools makes it warn as deprecated, so the full suite fails for reasons that have nothing to do with the change.
- **Revealjs slides are PowerPoint slides at 96 px to the inch.** 1280 x 720 px is 13.33 x 7.5 in, so `knit_reveal_table()` runs a flextable through `slide_table_pages()` with `reveal_table_area()` (the deck's `width`/`height` from `quarto_format()$metadata`, Quarto 1.5 included), and gt and reactable take a size from `reveal_text_size()`. Unlike PowerPoint, where a table sits at `ft.top`, text above a revealjs table pushes it down the slide, so `reveal_margins` keeps 1.5 in at the top for two lines of text (a sentence adds about 56 px, two bullets 140 px, three 197 px); without it a 12-row table under two bullets ran past the footer. The render test measures each slide's lowest point against `.reveal .footer` in headless Chrome, and it must run against the *installed* package: Quarto renders in its own R process, so `load_all()` changes don't reach it. A `---` that a chunk prints stays inside Quarto's `.cell` Div and does not start a slide; `phw-reveal-tables.lua` lifts a cell holding a rule and a raw HTML table to the top level. It lifts only the cell's `cell-output-display` Divs: a `tbl-` chunk's float reaches a pre-quarto filter as a Div too, and dissolving it loses the numbered caption and the `@tbl-` reference. Its `FloatRefTarget` pass keeps the first page in the float and puts the rest after it. A float handler that returns its own `float` inside a list makes Quarto drop it, so the first page goes in a new `quarto.FloatRefTarget({...})` (works in Quarto 1.5 and 1.11). Keep flextable's `knit_meta` when pasting its pages: without its dependencies there is no shadow DOM, and reveal's `p` margins and `td` borders blow the rows up. `gt::gt_split()` fails on a `phw_gt()` table (its substitutions keep the full row count), so gt can't continue over slides. Measure a table's bottom on each slide with headless Chrome (`--dump-dom --virtual-time-budget`, a script that calls `Reveal.slide(i)` and divides by `Reveal.getScale()`); the flextable sits in a `.flextable-shadow-host`.
- **flextable 0.10.5 changed what `line_spacing()` means in HTML.** Before, `space = 1.25` wrote `line-height: 1.25` (times the text size). From 0.10.5 it writes the spacing times the font's own line height (`gdtools::font_line_metrics()`, 1.149 for Ubuntu), so `line-height: 1.436`, plus a negative top margin that nets to zero. `row_heights()` assumes 1.25, so on 0.10.5 every revealjs flextable row was about 4 px taller than sized, and a 12-row table under two bullets ended 20 px into the footer on CI's `ubuntu-latest` only (the other jobs had 0.10.4 binaries). `html_line_spacing()` divides by `systemfonts::font_info()$lineheight` on 0.10.5 and later. When a render test passes locally but fails on CI, compare the package versions in the CI log (`flextable  0.10.5`) with the local library first: installing CI's versions into your own library reproduced CI's measurements to the pixel. 0.10.5 also rescales PowerPoint line spacing by line height / 1.2 (lines get shorter there, so no overflow).
- **A knitted PowerPoint table sits at a fixed `ft.top`, so text above it is overprinted unless the top leaves room** (#463). `text_room_top()` puts it two lines of the master's body text below the content placeholder of the Title and Content layout: 2.6 in on the PHW deck. flextable reads `ft.top` only from `knitr::opts_current`, which knitr locks while a chunk runs (`opts_current$set()` warns, and will error). So `knit_slide_table()` rewrites the `y` of `<a:off>` in flextable's XML instead. Using `$lock(FALSE)` would leave the lock state wrong when `knit_print()` runs outside a chunk, as some tests do. LibreOffice renders only the first slide of a deck built on officer's `template.pptx`; read its table positions from the XML.
