# Choosing a legend for every chart

- **A theme can't choose a legend.** No theme element sets `nrow` or the guide class, and ggplot2 4.0 resolves each scale's guide (`Guides$setup()`) before any palette runs, so a theme palette that receives the scale as `self` is too late to change `self$guide`.
- **The `ggplot2.discrete.*` options clash with theme palettes on 4.0.** `theme()` warns "options(...) setting is incompatible with the palette theme setting" whenever a discrete palette element is set while the option is set, so `use_phw_ggplot()` sets those options only before 4.0. Every later `theme_phw()` would warn.
- So `wrap_legends()` swaps in `phw_guide_legend()` where phwstyle draws a chart: `phw_save()`, `phw_finalise()`, `phw_arrange()`, `phw_add_slide()`, and knitr's `render` chunk option in the `phw_*_document()` formats. Plain `print()`, `ggsave()` and Quarto don't go through it.
- A guide's `draw()` runs while the target device is open, so `grid::unit(1, "npc")` there is the width the chart is drawn at. `phw_finalise()` builds its gtable before that size is known, so `makeContext.phw_finalised()` builds it again when drawn.
- knitr's default `render` adds the class `knit_asis_htmlwidget` to htmlwidget output (for figure captions); a custom `render` has to do the same.
- patchwork places a collected bottom or top legend under the panels (`attach_guides()`): from the left of the first panel when it fits, centred on them when it is wider. It ignores `legend.location`. `phw_guide_legend()` wraps every collected legend to the image's width inside the figure's margins (`collected_room()`), then `makeContext.phw_placed_legend()` moves it, when drawn, to the title's left edge (patchwork's title columns, 3 to n - 2), or further left if it would run off the right edge. It is a wrapper of the same size around the legend, because ggplot2's `package_box()` overwrites each legend's own viewport. Wrapping to the panel span alone wrapped two legends of full health-board names to 6 + 1 rows and squashed the panels (#408), and wrapped a map's board legend to one column under a second legend (#467). A test of a collected legend must check where it starts and ends, not only its width (#391). Test data needs varying values: a constant `cases = 20` gives y labels like "19.975", which widen the axis.
- Measure legend widths on `ragg::agg_png()`, as `phw_save()` draws. Base `png()` has no PHW font, so its text is narrower and a legend that runs off looks as if it fits.
- **A fixed-shape panel centres a narrower figure.** With a map, patchwork's `respect` makes grid shrink the layout and centre it, so summing `g$widths` misses the slack. Any room measured from the figure feeds back: a legend wrapped to the narrowed figure takes more rows, which makes the map shorter and so narrower (#419, #467). The image's width does not depend on the figure, so the legend wraps to that. **Measure positions when drawn, not ahead.** `phw_save()` fits the captions and `phw_finalise()` adds a footer after `phw_arrange()` returns, so a figure measured in `collected_room()` is not the one drawn: a title edge measured there put a legend 0.5 cm off it. `makeContext()` of the placed legend reads `current.vpPath()`, goes up to the viewport that holds the `guide-box.t-l-b-r` cell (the figure's layout) and reads `deviceLoc()` there. `makeContext()` must leave the viewport where it found it.
- **patchwork places a collected legend by the figure's theme** (`plot_annotation(theme = )`, read by `assemble_guides()`), not the plots' themes, which the guide's `draw()` receives. So `phw_arrange()` passes the figure's `legend.justification` to `collected_room()`. Reading it from the plot's theme broke a stacked figure of maps once `theme_phw_map(legend = "bottom")` centred its legend (#437).
- **A single map's bottom legend is centred** by `theme_phw_map()`: grid shrinks a fixed-shape plot and centres it, so a left-justified legend started at the map's edge but wrapped to the image width and ran off (#437).
